# Native development and guarded runtime policy

Authorization: November 2, 2026. This replaces older Muse-first coding ownership,
premium-only review roles and historical fixed-credit limits in this policy.
Product safety, evidence and lane ownership in AGENTS.md still hold.

## Native coding workflow

1. Use one bounded feature packet: goal, acceptance criteria, branch, exact owned
   source/test paths, contract decisions, actual checks, failed-repair count,
   blockers and next action. Parallel agents use separate checkouts and disjoint
   paths. Do not duplicate active tasks or judges.
2. Native Codex Sol/Terra and terminal Claude Code with explicit Sonnet selection
   may implement, write tests, run offline checks and repair their assigned scope.
   Claude uses the existing subscription login; no new API-key billing route or
   Fable/Haiku fallback. If rate-limited, checkpoint and let native Codex continue.
3. Run affected repository checks directly. Native coding, offline checks and
   read-only Proof verification require neither run.mjs nor Meta settings nor
   META_GUARD_HOME. Missing prerequisites block only operations needing them.
4. After two unsuccessful repairs, obtain one targeted diagnosis with the smallest
   reproduction and actual outputs. Make one bounded repair; if still blocked,
   checkpoint and stop. Do not reset counts after compaction.
5. Obtain a fresh independent Sol/Terra review of the entire green diff, including
   new tests, criteria and actual check outputs. Native Codex review subagents use
   fork_turns="none" and only the bounded packet. Repair concrete review findings
   with at most two attempts; re-review findings and regression impact only.
6. Before authorized push/publication, verify reviewed paths and the exact candidate
   head with independent review and passing appropriate local checks. Before merge,
   all required remote checks must pass on the exact reviewed published head.
   Offline success is never a physical evidence claim.

Native automatic compaction stays enabled at normal thresholds. Use concise
checkpoints rather than historical transcripts. Claim compaction only with a
runtime event proving it occurred.
